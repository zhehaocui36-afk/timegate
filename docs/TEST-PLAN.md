# 测试计划（S02）

> **版本** v1.0 · **状态** 已冻结（G1 出口） · **更新** 2026-11-09
> 定义五类测试的范围、用例明细与设备矩阵。S12 按本计划实现测试与 CI 门禁；S11 按真机用例执行走查。

## 1. 范围与目标

- 覆盖 `docs/REQUIREMENTS.md` 全部 P0 需求；P1 需求覆盖主要路径。
- 核心逻辑（`day_key`、计时、闸门状态机）行覆盖率目标 ≥ 80%（G2 门禁）。
- 用例 ID 前缀：`UT` 单元 / `IT` 仪器 / `DT` 真机 / `AT` 无障碍 / `ST` 安全 / `MT` 人工。

## 2. 五类测试说明

| 类型 | 运行环境 | 覆盖重点 | 责任工包 |
|---|---|---|---|
| 单元 UT | JVM（`testDebugUnitTest`） | 纯逻辑：时间口径、状态机、权限归约、去重 | S06/S07/S08/S09 |
| 仪器 IT | 模拟器或设备（`connectedDebugAndroidTest`） | Room DAO、Compose UI 流程、边界交互 | S12 |
| 真机 DT | Find X8 / ColorOS 17 | 系统层行为：检测、服务、息屏、拦截 | S11 |
| 无障碍 AT | TalkBack + 代码审计 | 读屏可达、自我限权、降级 | S12 |
| 安全 ST | 静态扫描 + 代码审计 | 权限、exported、内容读取、网络 | S12 |
| 人工 MT | 文档核对 + 手工走查 | 配置类、文案类、文档一致性 | 各工包 + S12 复核 |

1. S06/S07/S08/S09 各自交付时跑通所属 UT，作为 S09 前单测基线。
2. S12 补齐 IT/AT/ST 并接入 CI 门禁（Lint 0 error、单测全绿、无 INTERNET、密钥扫描）。
3. S11 用 Find X8 跑 DT 与 MT-04，产出 `docs/QA-REPORT.md`。
4. G2（S12 结束）要求：P0 追踪全覆盖、核心逻辑覆盖率 ≥ 80%、五条真机自检全过。
