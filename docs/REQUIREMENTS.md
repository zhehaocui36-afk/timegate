# 需求基线（S02）

> **版本** v1.0 · **状态** 已冻结（G1 出口） · **更新** 2026-11-09
> 依据 `docs/REQUIREMENTS-FREEZE-v1.0.md`（唯一需求入口）与 `HANDOFF.md` E/F/G/H 节、`demo.html` 交互改写。
> 本文件是 S03 起各工包的需求口径；新增需求只进 V1.1，不在此插队。

## 阅读约定

每条需求固定五段：`ID` / `优先级` / `前置条件` / `动作` / `可观察结果`。P0 需求追加 `验收标准`（量化、可判定）。

- **优先级**：P0 = 核心闭环（缺了机制失效）；P1 = 增强但非阻断。
- **可观察结果**：描述动作完成后外部可见、可量测的现象，禁止出现「等 / 适当 / 尽量」这类模糊词。
- **术语**：沿用 `docs/SOP.md` §0.2 术语表（闸门 / 受管应用 / 到时 / 门禁 / 走查）。

**范围排除清单（V1 明确不做，不计需求 ID）**：每日总预算、21:30 复盘推送、CSV/JSON 导出、多设备同步、好友 PK、45/60 分钟专注档、iOS。上述功能在代码中不得出现入口。

## 1. 范围与平台

### R-01 · 平台仅限 Android

- **优先级**：P0
- **前置条件**：无。
- **动作**：只交付 Android 应用；不交付 iOS 应用。
- **可观察结果**：仓库中不存在任何 iOS 工程或 iOS 构建产物；iOS 在文档中标注「不做」。
- **验收标准**：仓库目录树中无 `.xcodeproj` / `.xcworkspace` / Swift 源文件；`PROJECT.md` 平台栏为「Android only」。

### R-02 · 零网络权限

- **优先级**：P0
- **前置条件**：无。
- **动作**：合并后的 `AndroidManifest.xml` 不声明 `INTERNET` 权限；不引入任何联网 SDK。
- **可观察结果**：应用进程无网络套接字能力；`aapt dump permissions` 输出不含 `android.permission.INTERNET`。
- **验收标准**：合并 Manifest 权限清单中 `INTERNET` 出现次数为 0；CI 中「无 INTERNET」检查通过。

### R-03 · 最低系统版本

- **优先级**：P0
- **前置条件**：无。
- **动作**：`minSdk` 设为 26（Android 8.0），`targetSdk` 跟随构建时最新稳定版本。
- **可观察结果**：APK 可安装到 Android 8.0 及以上设备。
- **验收标准**：`app/build.gradle.kts` 中 `minSdk = 26`；Debug APK 在 API 26 模拟器安装成功。

### R-04 · 分发通道仅 GitHub Releases

- **优先级**：P1
- **前置条件**：R-02 成立。
- **动作**：只通过 GitHub Releases 分发签名 APK；不上任何应用商店。
- **可观察结果**：README 与发布文档中无任何商店上架步骤。
- **验收标准**：README「安装」节仅指向 GitHub Releases 链接。

## 2. 首次配置

### R-10 · 引导三步不可跳过

- **优先级**：P0
- **前置条件**：应用首次启动，未完成引导（`onboarded=false`）。
- **动作**：依次展示「教程 3 屏 → 权限 → 选受管应用」；教程必须先于选应用。
- **可观察结果**：未完成引导时无法进入首页四 Tab；每屏只有「下一步」无「跳过」。
- **验收标准**：清除数据后冷启动，首页不可见，仅引导页可见；教程屏、权限屏、选应用屏依次出现。

### R-11 · 权限跳系统页并回读真实状态

- **优先级**：P0
- **前置条件**：处于权限引导屏。
- **动作**：每项权限点击后跳转到对应系统设置页；返回时在 `onResume` 回读真实授权状态并刷新显示。
- **可观察结果**：授权状态与系统设置一致；不存在「点一下算授权」的占位状态。
- **验收标准**：真机关闭某项权限后从系统设置返回，该权限显示「未开启」；开启后显示「已开启」。

### R-12 · 必需项缺失阻断，可选项缺失放行

- **优先级**：P0
- **前置条件**：处于权限引导屏。
- **动作**：5 项必需权限任一未授予时，「继续」按钮禁用；2 项可选权限未授予时允许继续，并在该行显示后果说明。
- **可观察结果**：缺任一必需项时点「继续」无响应；缺可选项时「继续」可点，页面显示后果文案。
- **验收标准**：关闭任一项必需权限，继续按钮为 `disabled`；关闭任一项可选权限，继续按钮可点且显示后果文案。

### R-13 · 选受管应用至少 1 个

- **优先级**：P0
- **前置条件**：通过权限引导屏。
- **动作**：展示可管理应用列表，默认勾选当日使用时长最高的 3 个；用户可增删勾选，但总数不得为 0。
- **可观察结果**：勾选数为 1 时再取消最后一个不生效；确认后受管应用列表包含勾选项。
- **验收标准**：尝试取消最后一个勾选时列表保持不变并提示；确认进入首页后受管应用数 ≥ 1。

## 3. 权限矩阵与降级

### R-20 · 五项必需权限

- **优先级**：P0
- **前置条件**：应用已安装。
- **动作**：声明并引导授予 5 项必需权限：`PACKAGE_USAGE_STATS`、`SYSTEM_ALERT_WINDOW`、`POST_NOTIFICATIONS`、`FOREGROUND_SERVICE`（含 `specialUse`）、`REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`。
- **可观察结果**：5 项任一未授予时，对应能力不可用：统计为 0、闸门不弹、无常驻通知、计时被系统杀、息屏即失效。
- **验收标准**：`docs/PERMISSIONS.md` 列出 5 项权限、用途、授权路径与「不给的后果」；Manifest 声明与文档逐项一致。

### R-21 · 两项可选权限

- **优先级**：P0
- **前置条件**：应用已安装。
- **动作**：声明并引导授予 2 项可选权限：`RECEIVE_BOOT_COMPLETED`（自启动）、`BIND_ACCESSIBILITY_SERVICE`（无障碍）。
- **可观察结果**：自启动未授予时重启后需手动打开一次；无障碍未授予时「到时退出」只撤遮挡不回桌面。
- **验收标准**：`docs/PERMISSIONS.md` 列出 2 项可选权限及「不给的后果」，并标注为可选增强。

### R-22 · 权限降级（无障碍关闭仅撤遮挡）

- **优先级**：P0
- **前置条件**：到时时用户未授予无障碍权限。
- **动作**：检测无障碍开关状态；关闭时「退出」只执行撤遮挡，不调用 `performGlobalAction(GLOBAL_ACTION_HOME)`，不伪装回桌面成功。
- **可观察结果**：无无障碍时点击「退出」后闸门遮挡消失，但停留在受管应用前台；无崩溃、无假成功提示。
- **验收标准**：真机关闭无障碍后走到时页点「退出」，闸门 Activity 关闭、目标应用仍在前台。

### R-23 · `<queries>` 声明 LAUNCHER

- **优先级**：P0
- **前置条件**：无。
- **动作**：Manifest 通过 `<queries>` 声明 `android.intent.action.MAIN` / `CATEGORY_LAUNCHER`，用于枚举可管理应用。
- **可观察结果**：应用列表能列出设备已安装的启动器应用；不声明时列表为空。
- **验收标准**：真机选应用页能列出已安装应用，非空。

### R-24 · 无障碍自我限权

- **优先级**：P0
- **前置条件**：用户授予无障碍权限。
- **动作**：无障碍服务只订阅 `typeWindowStateChanged`，只读 `event.getPackageName()`；不申请 interactive windows；不调用 `getText()` / `getContentDescription()`。
- **可观察结果**：代码库中不出现上述读取屏幕内容的方法调用；无障碍配置 `canRetrieveWindowContent="false"`。
- **验收标准**：代码审计（grep）对 `getText(`、`getContentDescription(` 命中数为 0；无障碍 XML 配置关闭内容读取。

## 4. 前台检测

### R-30 · UsageStats 2 秒轮询检测前台

- **优先级**：P0
- **前置条件**：已授予 `PACKAGE_USAGE_STATS`。
- **动作**：以 `UsageStatsManager.queryEvents` 为主检测源，轮询周期 2 秒，识别当前前台包名。
- **可观察结果**：打开受管应用后 2 秒内产生一次前台事件。
- **验收标准**：真机打开受管应用，日志在 2 秒内出现对应包名前台事件。

### R-31 · 无障碍仅作可选加速

- **优先级**：P1
- **前置条件**：已授予无障碍权限。
- **动作**：无障碍作为第二检测源，只用于提前 0–200ms 拿到前台包名；两路写同一仓库并去重。
- **可观察结果**：无障碍关闭时检测仍工作；开启时仅提前不超过 200ms。
- **验收标准**：关闭无障碍后 R-30 仍通过；开启后首次检测时间差 ≤ 200ms。

### R-32 · 前台事件去重

- **优先级**：P0
- **前置条件**：检测服务运行中。
- **动作**：同一受管应用连续前台事件在去重窗口内只触发一次闸门；切到其他应用再切回时重新触发。
- **可观察结果**：连续打开同一应用不重复弹闸门；切换应用后再打开会弹。
- **验收标准**：单测覆盖去重逻辑；真机连续打开同一应用只弹一次闸门。

### R-33 · 检测失败不阻塞用户

- **优先级**：P0
- **前置条件**：检测服务拿不到前台包名。
- **动作**：检测失败时记录日志，不弹闸门，不阻断用户操作。
- **可观察结果**：检测失败时不出现任何弹窗或崩溃，应用照常运行。
- **验收标准**：模拟前台包名为空，应用无弹窗、无崩溃，日志有失败记录。

### R-34 · 忽略自身与桌面

- **优先级**：P0
- **前置条件**：检测服务运行中。
- **动作**：前台包名为本应用或系统桌面（launcher）时不触发闸门。
- **可观察结果**：打开本应用自身或回到桌面，不弹闸门。
- **验收标准**：单测覆盖「自身 / 桌面」包名过滤；真机回到桌面无闸门。

## 5. 闸门状态机

### R-40 · 闸门状态机

- **优先级**：P0
- **前置条件**：检测到受管应用前台事件。
- **动作**：状态机按 `IDLE → DURATION → INTENT → ALTERNATIVE → IN_USE → TIMEOUT` 迁移；每一步提供「直接退出」回到 `IDLE` 并记 abandoned。
- **可观察结果**：状态迁移与状态图一致，不存在非法跳转。
- **验收标准**：单测覆盖全部状态迁移与「直接退出」回退路径，覆盖率达标。

### R-41 · 时长选择 5 / 15 / 自定义 1–120

- **优先级**：P0
- **前置条件**：闸门处于 `DURATION` 状态。
- **动作**：提供 5 分钟、15 分钟两档，及自定义滑杆 1–120 分钟。
- **可观察结果**：选择档位或自定义值后，进入意图页时承诺时长与所选一致。
- **验收标准**：Compose 仪器测试校验 5 / 15 / 自定义 1 / 自定义 120 四组边界值传入计时页。

### R-42 · 意图满 2 字才能继续

- **优先级**：P0
- **前置条件**：闸门处于 `INTENT` 状态。
- **动作**：输入框去首尾空格后长度 < 2 时「继续」按钮禁用；≥ 2 时启用；不弹错误弹窗。
- **可观察结果**：输入 1 字时继续按钮为禁用态；输入 2 字时变可用。
- **验收标准**：仪器测试覆盖 0 / 1 / 2 字三种输入，按钮状态分别禁用 / 禁用 / 启用。

### R-43 · 替代三选

- **优先级**：P0
- **前置条件**：闸门处于 `ALTERNATIVE` 状态。
- **动作**：提供「我先去做」（记 abandoned，不扣时长，提示省下 N 分钟）与「还是想打开」（放行进入 `IN_USE`）两个主动作，及「直接退出」。
- **可观察结果**：点「我先去做」闸门关闭、`gate_log.abandoned` 计数加 1、不产生计时；点「还是想打开」进入倒计时页。
- **验收标准**：单测校验 abandoned 计数递增且无 usage_session 产生；仪器测试校验放行进入计时。

### R-44 · 每步「直接退出」记 abandoned 不扣时长

- **优先级**：P0
- **前置条件**：闸门处于 `DURATION` / `INTENT` / `ALTERNATIVE` 任一状态。
- **动作**：每步底部提供「直接退出」；点击后回到 `IDLE`，记录一条 abandoned，不扣减任何时长。
- **可观察结果**：直接退出后 `gate_log.abandoned` 加 1，`usage_session` 无新增。
- **验收标准**：单测覆盖三步各自的直接退出，断言无 usage_session 写入。

### R-45 · 闸门顺序固定

- **优先级**：P0
- **前置条件**：无。
- **动作**：三问顺序固定为「时长 → 意图 → 替代」，不可换序、不可跳过。
- **可观察结果**：任何路径都按该顺序经过三问。
- **验收标准**：状态机迁移测试确认不存在 DURATION 直达 ALTERNATIVE 的路径。

### R-46 · 闸门用透明 Activity

- **优先级**：P0
- **前置条件**：无。
- **动作**：三问闸门用透明主题 `GateActivity` 实现，不使用悬浮窗。
- **可观察结果**：闸门三问可输入文字，输入法弹起时不崩溃。
- **验收标准**：闸门 Activity 主题为透明，输入意图时输入法正常弹出且界面不崩。

## 6. 计时

### R-50 · 前台服务计时与常驻通知

- **优先级**：P0
- **前置条件**：闸门放行进入 `IN_USE`。
- **动作**：启动前台服务计时，通知栏展示常驻通知，实时显示剩余时间。
- **可观察结果**：计时期间通知栏持续存在倒计时通知。
- **验收标准**：真机计时中通知栏可见常驻通知，剩余时间递减。

### R-51 · 剩 1 分钟预警

- **优先级**：P0
- **前置条件**：计时剩余时间降至 1 分钟。
- **动作**：剩余 ≤ 60 秒时发出一次预警（视觉提示 + 震动）。
- **可观察结果**：倒计时进入最后 1 分钟时页面出现预警提示并震动一次。
- **验收标准**：真机或加速计时在剩 1 分钟时触发一次预警，不重复触发。

### R-52 · 只存时间戳不存剩余秒

- **优先级**：P0
- **前置条件**：进入计时。
- **动作**：计时只记录开始 / 离开 / 结束时间戳；剩余时长每次按当前时刻实时计算。
- **可观察结果**：数据层不存在「剩余秒数」字段。
- **验收标准**：单测校验回前台后按离开时刻补算剩余，误差 ≤ 1 秒。

### R-53 · 提前结束按实际分钟计

- **优先级**：P0
- **前置条件**：计时中用户点击「提前结束」。
- **动作**：按实际已用分钟计入，向上取整且最少 1 分钟。
- **可观察结果**：使用 30 秒提前结束计入 1 分钟；使用 3 分 10 秒计入 4 分钟。
- **验收标准**：单测覆盖 30 秒 → 1 分钟、3 分 10 秒 → 4 分钟两组边界。

### R-54 · 息屏 / 后台计时准确

- **优先级**：P0
- **前置条件**：计时进行中设备息屏 10 分钟或切后台。
- **动作**：回前台时按时间戳补算，倒计时反映真实经过时间。
- **可观察结果**：息屏 10 分钟后回来，倒计时少了 10 分钟，不停在息屏时刻。
- **验收标准**：真机息屏 10 分钟，回来倒计时误差 ≤ 5 秒。

### R-55 · 服务强停后自起

- **优先级**：P0
- **前置条件**：前台服务被系统或用户强停。
- **动作**：服务以 `START_STICKY` 启动，被强停后由系统尝试重启。
- **可观察结果**：强停后重开应用，前台服务恢复运行。
- **验收标准**：真机强停后重开，常驻通知恢复。

### R-56 · Android 14 前台服务类型

- **优先级**：P0
- **前置条件**：目标设备为 Android 14+。
- **动作**：前台服务声明 `foregroundServiceType="specialUse"` 并带 `PROPERTY_SPECIAL_USE_FGS_SUBTYPE` 属性。
- **可观察结果**：Android 14+ 设备上服务启动不抛 `MissingForegroundServiceTypeException`。
- **验收标准**：Android 14+ 模拟器启动计时服务无异常。

## 7. 到时与三出口

### R-60 · 到时全屏拦截

- **优先级**：P0
- **前置条件**：承诺时长归零。
- **动作**：展示全屏「时间到」页，覆盖当前应用，展示理由与替代动作回顾。
- **可观察结果**：归零瞬间全屏「时间到」页盖住受管应用，无法继续操作目标应用。
- **验收标准**：真机加速计时到点，全屏「时间到」页出现且遮挡目标应用。

### R-61 · 出口一：退出回桌面 / 撤遮挡

- **优先级**：P0
- **前置条件**：处于「时间到」页。
- **动作**：点「退出」时，若有障碍权限则 `performGlobalAction(GLOBAL_ACTION_HOME)` 回桌面；无则只撤遮挡。
- **可观察结果**：有障碍时回到系统桌面；无障碍时闸门关闭、停留在目标应用。
- **验收标准**：真机有障碍时「退出」回桌面；关闭无障碍时「退出」只撤遮挡（与 R-22 一致）。

### R-62 · 出口二：再继续回时长弹窗

- **优先级**：P0
- **前置条件**：处于「时间到」页。
- **动作**：点「再继续」后回到 `DURATION` 状态重新选时长，不固定续杯。
- **可观察结果**：回到时长弹窗；连续多次「再继续」每次重新选时长。
- **验收标准**：单测校验「再继续」回到 `DURATION`；连续 3 次「再继续」均回时长弹窗。

### R-63 · 出口三：转去专注 10 分钟

- **优先级**：P0
- **前置条件**：处于「时间到」页。
- **动作**：点「转去专注」后进入 10 分钟短专注流程。

## 8. 时间口径

### R-70 · 凌晨 4:00 换日

- **优先级**：P0
- **前置条件**：无。
- **动作**：跨天以本地时间 04:00 为界；04:00 前的记录归前一天，04:00 起归当天。

### R-71 · day_key 本地拼日期

- **优先级**：P0
- **前置条件**：无。
- **动作**：`day_key` 用本地年月日拼成 `YYYY-MM-DD`，禁止用 `toISOString().slice(0,10)` 等 UTC 截断方式。
- **可观察结果**：东八区 00:30 的记录 `day_key` 为当天（而非 UTC 的昨天）。
- **验收标准**：单测覆盖跨年、闰年、时区三类用例，东八区凌晨结果正确。
