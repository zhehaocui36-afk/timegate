# A. 对话快照

## A.1 起点

用户提供两样东西：
1. `shijiansuo.apk` —— 何同学 2021 年做的「时间锁」，已停止维护
2. B 站视频 `BV1ev411x7en` —— 该 App 的发布视频

诉求：复刻其核心功能（限制与统计手机使用时长），但原版 UI 陈旧、易用性差、教程已失效，需要重做。

## A.2 APK 逆向结论（实测，非推测）

| 项 | 值 |
|---|---|
| 包名 / 版本 | `com.application.limits` · v1.0.6（versionCode 5） |
| 技术栈 | 纯 Kotlin + Java，AndroidX + Material 2 + Navigation + MotionLayout，**无 Flutter/RN，无 .so** |
| 体积 | 5.80 MB / 1089 个文件，**未加固、未混淆**（141 个自有类名全可读） |
| 兼容 | minSdk 22 / targetSdk 30（Android 11），停留在 2021 年 |
| 架构 | 9 Activity + 常驻服务 `LockScoutService`（START_STICKY 轮询，**清单里 `exported=true`**）+ 开机广播 |
| 存储 | SharedPreferences + Gson，无数据库、无账号、无联网上报 |
| 机制 | 入限额列表 → 打开时输时长（5/15/30，上限 6h）→ UsageStats 统计 → 到点弹悬浮窗 → `killBackgroundProcesses` 强杀 |

**它的三个死穴**
- 零 `values-night`，没有暗色模式；图标全是 PNG 位图（`ic_arrow.png` 仅 277B）
- FAQ 是 7 个外链指向 `support.qq.com/products/301180/faqs/85325~85331`，服务器一关教程即废
- 首次使用跨 4~5 个页面分散授权，用户不知道还差几步

**它丢掉了最关键的一半**
视频里 40 人五组实验：小屏 −7.2%、App 限额 −14.1%、全局限额 −15.9%、黑白屏 −14.6%、**时间锁 −41.0%**。那 41% 来自打开前的三问。而 1.0.6 只剩「输入时长」和「限额时间已到」——**只剩记账，没了觉察**。

## A.3 决策轨迹（含被否决的方案）

| # | 议题 | 最终决定 | 被否决的方案与原因 |
|---|---|---|---|

# B. 产品定义

**一句话**：在打开受管应用之前，先问你三件事——为什么打开、用多久、放下它你能先去做什么。

**目标用户**：想减少手机使用时长的个人，不需要监督别人，也不接受说教。

**明确不做**：家长监督、好友 PK、云同步、账号体系、会员付费、判断"好应用/坏应用"。

**设计原则**
1. 说事实不说评价。文案里不出现"自律""坚持""加油"。
2. 只用一个强调色，占比 <5%，其余全是中性色。
3. 数字是主角，说明文字退到 11–13px。
4. 动效只用在有物理意义的地方（按压、位移、数值变化）。

# D. 页面结构

## D.1 主流程

```
首次启动
  ① 教程（是什么 / 隐私承诺）
  ② 授权（使用情况访问 / 悬浮窗 / 后台运行，三项全绿才能继续）
  ③ 选受管应用（默认勾选耗时最多的 3 个）
  → 首页

日常：点开受管应用
  ② 时长弹窗（sheet，底部常驻「直接退出」）   5 / 15 / 自定义
  ③ 第 2 问：你打开它想做什么？              ≥2 字才能继续
  ④ 第 3 问：放下它，你能先去做什么？        「我先去做」/「还是想打开」
  ⑤ 计时（全屏，剩 1 分钟预警）
  ⑥ 时间到（全屏）
        ├ 退出 → 回桌面
        ├ 再继续使用一会儿 → 回到 ② 重选时长
        └ 转去专注 10 分钟 → 专注页
```

## D.2 四个 Tab

| Tab | 内容 | 空状态 |
|---|---|---|
| **今日** | 构成环（按应用分段的甜甜圈）+ 图例 + 比昨天 + 「今天最想先放下」+ 专注入口 | 环全灰、文案「今天还没有记录」 |
| **应用** | 受管列表：图标 / 名称 / 已用 / 上限 / 细进度条，点行进闸门 | 「先管住一个最耗时的 App 试试」 |
| **统计** | 7 天柱图（今日实色、其余半透明）+ 按应用排行 + 闸门漏斗 | 柱子归零不崩 |
| **我的** | 主题 / 玻璃通透度 / 震动 / 时间加速 / 重新生成演示数据 / 清空 | — |

**为什么首页是构成环而不是进度环**：删掉总预算后，环失去了分母。现在每段颜色深浅代表一个应用占今天总时长的比例，中心显示总数——只回答"时间花在哪了"，不暗示"你该用多久"。

# E. 数据与交互逻辑

## E.1 数据模型（localStorage `tg.state.v2`）

```js
{
  v: 2,
  settings: {
    theme: 'dark',        // 'system' | 'light' | 'dark'
    glass: 60,            // 0–100，映射 --glass-blur 与 --glass-alpha
    speed: 1,             // 1 | 10 | 60，演示用时间倍率
    haptic: true,
    onboarded: false
  },
  apps: [
    { id: 'douyin', name: '抖音', short: '抖', quota: 60, used: 41, on: true }
  ],
  history: { '2026-11-09': 77 },   // dayKey → 当日总分钟
  gates: { total: 42, abandoned: 11 },
  focus: { count: 2, min: 50 }
}
```

## E.2 跨天规则

`dayKey = 本地日期(ts − 4h)`，即**凌晨 4:00 换日**。

理由：0 点重置等于每天白送一份额度，而 23:50 恰恰是最典型的失控点；凌晨 1 点刷手机在心智上属于"昨晚"，归前一天复盘卡的叙事才成立。

**禁止** `toISOString().slice(0,10)` —— 那是 UTC，东八区会整体偏 8 小时。

## E.3 闸门状态机

```
IDLE
 └─ 点受管应用 → DURATION（sheet）
      ├─ 直接退出 → 记 abandoned，回 IDLE
      └─ 继续 → INTENT
            ├─ 直接退出 → 记 abandoned
            └─ 文本 ≥2 字 → ALTERNATIVE
                  ├─ 直接退出 → 记 abandoned
                  ├─ 我先去做 → 记 abandoned，提示「省下 N 分钟」
                  └─ 还是想打开 → IN_USE
                        ├─ 提前结束 → 按实际时长计入
                        └─ 归零 → TIMEOUT
                              ├─ 退出 → 计入 N 分钟，回桌面
                              ├─ 再继续 → 计入，回 DURATION
                              └─ 转去专注 → 计入，进专注
```

## E.4 计时规则

1. **只存时间戳，不存"剩余秒数"**，剩余每次现算。
2. 锚点时钟 `wall() = 加载时 Date.now() + (performance.now() − 锚点)`，避开系统校时。
3. 时间加速**分段累加**（切换倍率先结算当前段），不能最后统一乘。
4. 渲染用 `requestAnimationFrame`，另加 1 秒心跳兜底（rAF 在后台标签页会停摆）。
5. 页面被系统回收后恢复：读 `tg.active`，`now − lastTickAt > 60s` 按离开时刻结账。

## E.5 边界情况

| 情况 | 处理 |
|---|---|
| 意图不足 2 字 | 「继续」按钮 `disabled` |
| 自定义时长 | 滑杆 1–120，默认 30 |
| 提前结束 | 按实际分钟计入，最少 1 分钟 |
| 用户点「我先去做」 | 不扣时长，只让 `gates.abandoned++` |
| 连续三次「再继续」 | 允许（原型不做惩罚；原生版建议加冷却） |

# F. 设计系统

## F.1 颜色（Apple 语义色，两套）

| 语义 | 深色 | 浅色 |
|---|---|---|
| 页面底 | `#000000` | `#F2F2F7` |
| 卡片 | `#1C1C1E` | `#FFFFFF` |
| 次级面 | `#2C2C2E` | `#E9E9EE` |
| 主 / 次 / 三级文字 | `#FFFFFF` / `rgba(235,235,245,.60)` / `.34` | `#000000` / `rgba(60,60,67,.60)` / `.34` |
| tint（填充） | `#4E5CEC` | `#4655DB` |
| tint（前景：图标/文字） | `#5B6CFF` | `#3541C9` |
| 危险 | `#FF453A` | `#FF3B30` |

**tint 只出现在 5 处**：tab 选中、开关、环形分段、图表、可点文字。别处一律黑白灰。

## F.2 字号与圆角

字号：`30 / 24 / 22 / 17 / 16 / 15 / 13 / 12 / 11 / 10`
圆角：`8 / 10 / 12 / 16 / 22 / 999`（控件 / 卡片 / 面板 / 胶囊），弹窗顶部 28

## F.3 玻璃：只有两处真用 `backdrop-filter`

底部悬浮胶囊、弹窗遮罩。其余是"仿玻璃"（实色 + 顶光 + 暗边），因为纯色底上开 blur 没有意义。

**外层胶囊四层**
```css
background: color-mix(in srgb, var(--surface) calc(var(--glass-alpha) * 100%), transparent);
backdrop-filter: blur(var(--glass-blur)) saturate(180%);
box-shadow:
  inset 0 1px 0 rgba(255,255,255,.26),   /* 顶光 */
  inset 0 -1px 0 rgba(0,0,0,.55),        /* 底内阴影＝厚度 */
  0 0 0 .5px rgba(255,255,255,.13),      /* 暗化边缘 */
  0 16px 38px -16px rgba(0,0,0,.95);     /* 落影 */
```
再加 `::before` 三层：左上径向高光、右下弱反射、顶部线性高光。**这一层决定它是"玻璃"还是"半透明色块"**。

**内层选中胶囊**：`rgba(255,255,255,.13)` + `blur(10px)`，比外层亮一档。

## F.4 按钮

| 状态 | 表现 |
|---|---|
| 默认 | 主按钮 = 白/黑反色实心；次级 = 玻璃；幽灵 = 描边 |
| 悬停 | 亮 6% + 抬 1px（仅 `@media (hover:hover)`） |
| 按下 | `scale(.972)`，90ms，绑 `pointerdown` |
| 禁用 | 透明度 .3，无光无影 |
| 聚焦 | 3px `--tint-soft` 外环（`:focus-visible`） |

## F.5 动效

按压 90ms；松手走弹簧 `damping 1.0 / response .35`；选中胶囊 `translateX` + `cubic-bezier(.34,1.4,.64,1)` 420ms；弹窗上滑 420ms；数字 400ms。

**不要用 `@keyframes` 做手势相关动画**——它无法中途抓住反向。

## F.6 无障碍

`prefers-reduced-motion` / `prefers-reduced-transparency` / `prefers-contrast` 三个都要接；`@supports not (backdrop-filter)` 降级为实色；触控目标 ≥44px；正文对比度 ≥4.5:1。

# G. 发布：只发 GitHub

## G.1 权限清单

| 能力 | 权限 | 用户怎么给 | 要 root？ |
|---|---|---|---|
| 读各应用使用时长 | `PACKAGE_USAGE_STATS` | 设置里手动开「使用情况访问」 | 否 |
| 提醒盖在别的应用上 | `SYSTEM_ALERT_WINDOW` | 手动开「显示在其他应用上层」 | 否 |
| 后台持续计时 | `FOREGROUND_SERVICE` + `specialUse` | 安装即得 | 否 |
| 开机自启 | `RECEIVE_BOOT_COMPLETED` | 安装即得 | 否 |
| 通知 / 震动 | `POST_NOTIFICATIONS` / `VIBRATE` | 首次弹窗 | 否 |
| 列出可管理应用 | `<queries>` 声明 LAUNCHER intent | 清单里写 | 否 |
| 省电白名单 | `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` | 引导跳转 | 否 |
| **点「退出」自动回桌面** | **`BIND_ACCESSIBILITY_SERVICE`** | 手动开无障碍 | **否** |
| 强制停止目标 App | `FORCE_STOP_PACKAGES` | 拿不到 | **是** |
| 真正阻止 App 启动 | 无公开 API | — | **是** |

**三条硬结论**
1. 不需要 root 就能做 95% 的功能。
2. 「自动回桌面」卡在**无障碍权限**，不是 root。Android 10+ 不允许第三方随便发 HOME intent，只有 `AccessibilityService.performGlobalAction(GLOBAL_ACTION_HOME)` 能做。
3. 只有「强制停止别的 App」和「真正阻止启动」需要 root / 系统签名。原 App 的 `killBackgroundProcesses` 在 Android 10+ 对前台应用已失效。

## G.2 因为不上商店，这些可以放开

| 原顾虑 | 现在 |
|---|---|
| Play 会拒无障碍 | 不审核，无障碍可以做，「退出即回桌面」能真正实现 |
| 需要隐私政策 / 权限申报 | 不需要，但 README 必须写清每项权限干什么 |
| `QUERY_ALL_PACKAGES` 审核 | 不审核，仍建议用 `<queries>` 收敛 |
| 备案 / 软著 | 不需要 |

## G.3 不声明 `INTERNET`

教程内置，不需要 WebView，所以整个 App **没有联网能力**。这不是"承诺不上传"，是权限表里根本没有网络权限——最硬的可信度证明。

## G.4 无障碍的自我限权（必须做）

1. `accessibility-service` 只订阅 `typeWindowStateChanged`，不申请 `flagRetrieveInteractiveWindows`
2. 代码只取 `event.getPackageName()`，**绝不调用** `getText()` / `getContentDescription()`
3. README 与 App 内各写一遍「它能看什么、不能看什么」

## G.5 发布流程

```
git init → commit → push 到 GitHub
  ├─ Settings → Pages → main / root     → 网页原型有个可扫码的链接
  └─ Releases → tag v0.1.0 → 上传签名 APK
```

**发布纪律**
1. `*.jks` / `keystore.properties` 必须进 `.gitignore`——keystore 泄漏等于应用身份被劫持
2. 每个 release 的 `versionCode` 必须递增，否则覆盖安装失败
3. Release notes 里写清"本版本新增了什么权限"

## G.6 ColorOS 17 / OPPO Find X8 适配

**测试机基线**：OPPO Find X8（2024 年 10 月，天玑 9400）/ ColorOS 17（基于 Android 17）。

> Android 14 引入的前台服务类型强制、Android 15/16 收紧的后台启动 Activity，在 17 上只会更严不会放松。**ColorOS 自己的省电策略比 AOSP 更激进**，所以适配重点不在 AOSP 而在厂商层。

### 必须手动开的 5 项

| # | 能力 | 设置里搜关键词 | 典型路径 | 不给的后果 |
|---|---|---|---|---|
| 1 | 使用情况访问 | 「使用情况」 | 设置 → 应用 → 特殊应用权限 → 使用情况访问 | 统计全 0，到点根本不触发 |
| 2 | 悬浮窗 | 「悬浮窗」 | 设置 → 应用 → 特殊应用权限 → 显示在其他应用上层 | 闸门弹不出来（这是弹窗的前提，不只是提醒） |
| 3 | 自启动 | 「自启动」 | 设置 → 应用 → 自启动管理 | 重启手机后监控静默失效 |
| 4 | 后台运行 | 「耗电」 | 设置 → 电池 → 应用耗电管理 → 允许**完全后台行为** + 允许自启动 + 允许关联启动 | 息屏几分钟就被杀 |
| 5 | 无障碍（可选） | 「无障碍」 | 设置 → 系统设置 → 无障碍 → 已安装的服务 → 闸 | 「退出」只能遮挡，不能真的回桌面 |

> ColorOS 各版本菜单措辞会变（"特殊应用权限"有的版本叫"权限管理"），**用设置顶部的搜索框搜关键词最稳**。

### ColorOS 特有的三个坑

**① 应用速冻**
ColorOS 会把长期未用的应用冻结（图标变灰），被冻的 App 收不到任何广播，前台服务也不会自启。
→ 设置里搜「速冻」，把「闸」加入白名单；另外在多任务界面**下拉卡片加锁**，能显著降低被杀概率。

**② 睡眠待机优化**
夜间深度休眠会切断后台定时器与网络。我们的计时靠前台服务 + 时间戳补算，理论上不怕，但通知会消失。
→ 设置 → 电池 → 更多设置 → 关闭「睡眠待机优化」，或对「闸」单独豁免。

**③ 应用列表读取权限**
ColorOS 把"读取已安装应用列表"做成了独立开关，关掉后 `QUERY_ALL_PACKAGES` 和 `<queries>` 都返回空——表现为**应用列表是空的**，很容易误判成代码 bug。
→ 设置 → 权限管理 → 闸 → 其他权限 → 应用列表 → 允许。

### 装完必做的 5 条自检

1. **强制停止后重开** → 前台服务能自己起来
2. **息屏 10 分钟** → 回来倒计时还在走（不是停在息屏那一刻）
3. **重启手机** → 通知栏里有常驻通知
4. **打开受管 App** → 闸门能盖上去
5. **到点** → 能拦截，「退出」能回桌面（需无障碍）

### 失效排查顺序

```
监控不工作
 ├─ 通知栏有没有常驻通知？
 │   ├─ 没有 → 服务被杀了：查 耗电管理 / 应用速冻 / 睡眠待机优化
 │   └─ 有   → 往下
 ├─ 打开受管 App 有没有闸门？
 │   ├─ 没有 → 查 悬浮窗权限 / 后台启动 Activity 限制
 │   └─ 有   → 往下
 └─ 计时准不准？
     ├─ 不准 → 查 使用情况访问 权限
     └─ 应用列表是空的 → 查 应用列表读取权限
```

### 对 Web 原型的影响

**没有影响**。ColorOS 自带浏览器与 Chrome 都支持 `backdrop-filter`、`100dvh`、CSS 变量、`env(safe-area-inset-*)`。
建议用 **Chrome** 打开 `https://<用户名>.github.io/<仓库名>/`，然后「添加到主屏幕」，全屏运行最接近原生。

系统里的"动画速度"（开发者选项的动画缩放）**不会影响** CSS 过渡时长，只会影响系统转场；我们自己的弹簧动效按 `prefers-reduced-motion` 走，与厂商设置解耦。

### P6 验收补充

Android 版必须在这台机器上跑通上面 5 条自检，**尤其是第 2 条（息屏 10 分钟）**——这是厂商省电策略最容易击穿的地方，模拟器上测不出来。

## P6 Android 要点

- **检测**：`UsageStatsManager.queryEvents` 2 秒轮询为主（授权门槛低），`AccessibilityService` 作可选增强（能提前 0–200ms 拿到前台包名），两路写同一 Repository 去重。
- **弹闸门**：透明主题的 `GateActivity`，不要用悬浮窗（三问要输入文字，悬浮窗在输入法弹起时必崩）。Android 10+ 后台启动 Activity 受限，**持有悬浮窗权限时才豁免**——所以悬浮窗权限是能弹闸门的前提，不只是提醒。
- **退出**：`performGlobalAction(GLOBAL_ACTION_HOME)`；拿不到无障碍就只做遮挡。
- **Android 14 前台服务**：`foregroundServiceType="specialUse"` + `PROPERTY_SPECIAL_USE_FGS_SUBTYPE`。
- **ROM 适配**：按 `Build.MANUFACTURER` 跳小米/华为/OPPO/vivo 自启动页，失败降级图文步骤。
- **Room**：`app_policy` / `usage_session` / `gate_log` / `focus_session` / `day_summary`，日期存 `day_key TEXT`，不要存 `Date`。

# I. 已经踩过的坑（别重复踩）

| 坑 | 现象 | 解法 |
|---|---|---|
| 按钮文字偏下 | 字体上伸部 > 下伸部，几何居中 ≠ 视觉居中 | `.btn` 用 `padding: 0 22px 3px` 做光学校正；改 1px padding 只移动 0.5px |
| 小按钮文字贴顶 | `.textlink` 用了 `display:block` + 固定高度 | 必须 `display:flex; align-items:center` |
| 环形分段看不见 | 段间距 4px 被圆头线帽吞掉 | 间距放到 16px |
| 截图"右侧被截断" | Edge 无头最小窗口 500px，`--window-size` 不生效 | 用 CDP `Emulation.setDeviceMetricsOverride`，别改 CSS |
| `toISOString()` 取日期 | 东八区整体偏 8 小时 | 用本地分量拼 `dayKey` |
| CSV 在 Excel 乱码 | 没有 BOM | Blob 首位加 `\uFEFF` |
| iOS `100vh` 被地址栏吃掉 | 底部被裁 | 一律 `100dvh` |
| 改数据后 UI 不更新 | `TG.store.state` 是静态引用 | 用 getter，`reset()` 后仍取当前值 |

# J. 给接手 agent 的硬要求

1. **不要改回绿色或金色**。配色已经过三轮否决，`#5B6CFF` 是用户拍板的。
2. **不要加回每日总预算**。用户明确说没用，首页的构成环就是为替代它而设计的。
3. **不要把三问做成可关闭的开关**。可关 = 用户第一天就关掉 = 机制失效。
4. **不要在 Web 版做"真实拦截"**。浏览器做不到，只能模拟；真拦截属于 P6 Android。
5. **文案里不要出现"自律/坚持/加油"**。也不要说"你真棒"。
6. **改动前先读 `PLAN.md`** 里的设计理由，很多看似奇怪的选择是有原因的。
